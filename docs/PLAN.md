## Задача

Тестовое задание Adrobot: обёртка над Keitaro Admin API.

1. **Создание кампании.** Форма: Name, Geo (`MX,AU,RO`), Offer (поиск с автокомплитом).
   Создаёт кампанию с доменом, группой и источником и двумя потоками:
   - поток 1: фильтр по стране из Geo → редирект на Google;
   - поток 2: все остальные → выбранный оффер.
2. **Редактор кампании.** Добавление и удаление офферов в существующей кампании.
   Кнопки работают, цифры верные. Подробное поведение: раздел «Поведение редактора» ниже.

**Сдача:** ссылка на GitHub с понятным README по миграциям и запуску. Стек: FastAPI + SQLAlchemy, фронт любой.

**Keitaro.** Админка: `https://tlgk.host/admin/`, API: `https://tlgk.host/admin_api/v1`, заголовок `Api-Key`.
- Документация API: [keitaro-openapi.yaml](keitaro-openapi.yaml) (OpenAPI 3.0, выгружена из админки
  `?object=adminApi.spec`). Сверяй с ней запросы и модели клиента, а не с памятью.
- Ключ: переменная `KEITARO_ADMIN_TOKEN` в `backend/.env` (в `.gitignore`). Ключ проверен: справочники отвечают 200.
- **Инстанс общий**: в нём кампании и группы других кандидатов (~275 кампаний). Ничего чужого не трогаем.
  Кампании `93212` из видео здесь нет.
- **Требование заказчика к именам:** кампании называем с префиксом `test_mirolyubov_`,
  например `test_mirolyubov_campaign1`. Касается всего, что создаём в трекере при проверках.
- **Наша тестовая кампания:** `test_mirolyubov_campaign1`, id 217109, создана через `POST /api/campaigns`
  2026-11-20 — часть 1 проверена вживую. Потоки: 1333642 (AU → google.com), 1333643 (default, оффер 18813
  100%). Используем для живых проверок редактора; чужие кампании не трогаем.
- **Домен `kylovoa.com` не резолвится в DNS**: переход по ссылке кампании проверить нельзя.
- **Что доступно по ключу (проверено GET, 2026-11-20):** домен `kylovoa.com` (id 1813),
  источник `FORTESTS` (id 836), группа кампаний `FORTESTS` (id 10332), один оффер `18813`.
  Id не хардкодим: ищем по имени из настроек.
- **Реальный формат потоков** (кампании других кандидатов, сделанные по тому же ТЗ):
  - гео-поток: `type=regular`, `position=1`, `schema=redirect`, `action_type=http`,
    `action_payload=https://google.com`, фильтр `{"name":"country","mode":"accept","payload":["MX"]}`;
  - поток офферов: `type=default` или `regular`, `position=2`, `schema=landings`, `action_type=http`,
    `action_payload=""`, `offers=[{"offer_id":..,"share":100,"state":"active"}]`;
  - payload фильтра — массив, хотя в спецификации указан string; закреплено контрактным тестом клиента.
  - типы действий (`GET /streams_actions`): редиректы `http`, `meta`, `js`, `curl` и др.

## Поведение редактора (по видео из ТЗ, https://youtu.be/jNloscEWCjA)

Эталон в видео: кампания `campaign 2`, домен `in.posdk.xyz`, группа и источник `FORTESTS`;
Flow 1: страна «Австралия» → `https://google.com`; Flow 2: три оффера по 33/33/34%.

**Загрузка.** Кнопка **Fetch streams from KT** забирает потоки кампании из Keitaro и сохраняет в нашу БД.
- Поток с офферами показывается таблицей офферов.
- Поток без офферов показывается только заголовком; его фильтры и редирект не парсим и не показываем.
- В заголовке потока: имя, позиция, `stream_id`, клики за сегодня.
- Оффер, который есть у нас, но пропал из Keitaro (удалили руками в трекере), при повторном Fetch
  не исчезает, а получает статус **removed**, как будто его удалили у нас.

**Таблица офферов потока.** Колонки: оффер (id, название, ссылка preview), Share (% + иконка пина),
Stats, Trends, Actions. Stats и Trends в видео пустые.

**Добавление.** Под таблицей: выпадающий поиск оффера с автокомплитом (ходит в наше API → Keitaro) и кнопка **Add**.
После добавления доли пересчитываются сразу: 4 оффера → по 25%.

**Удаление.** Кнопка **Remove**: оффер сереет, доля 0%, статус removed, остальные пересчитываются.
После публикации оффер исчезает из Keitaro, но у нас остаётся в архиве серым с кнопкой **Bring back**.
Bring back возвращает оффер в поток (снова пересчёт и публикация).

**Черновик и публикация.** Любое изменение (add, remove, bring back, pin) делает поток жёлтым:
есть неопубликованные изменения, Keitaro ещё не тронут (после обновления страницы в Keitaro всё старое).
- **Push to KT** отправляет текущий состав и доли в Keitaro, поток снова белый.
- **Cancel** откатывает черновик: офферы, добавленные до публикации, удаляются из нашей БД, поток снова белый.

**Пересчёт долей.** Сумма активных = 100%, removed = 0%.
- Без пинов: поровну, остаток раздаётся по 1% сверху списка (34/33/33; 38/37 + 25).
- **Пин**: закреплённая доля не меняется при любых add/remove/bring back;
  остальные делят `100 − сумма пинов` поровну (пример: пин 25%, два оффера → 38/37).
- Ссылка на % в колонке Share кликабельна: вероятно, ручной ввод доли (в видео не показано).

**Шапка страницы.** Хлебные крошки Campaigns / <кампания> / Keitaro Streams; кнопки Fetch streams from KT,
View in KT (ссылка на кампанию в трекере), Show all offers.

## Открытые вопросы

- **Только один оффер доступен по нашему ключу** (`18813`). Для проверки редактора (add, remove, доли)
  на живом Keitaro нужно хотя бы 2–3 оффера. Создать свои нельзя: `POST /offers` → 403
  «You have no permission to access this page - Offers» (проверено 2026-11-20). Спросить заказчика;
  до ответа редактор проверяем на моках.
- **Вопросы интерпретации ТЗ** (ручной ввод доли, последний оффер, пины, статистика и др.) —
  в [DISPUTED.md](DISPUTED.md). Открытые оттуда не реализовывать до решения.
