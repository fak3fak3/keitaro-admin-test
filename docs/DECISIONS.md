# Принятые решения

Журнал решений: только дописывается. Если решение пересмотрено, добавь новую запись
«Заменяет №N», а старую пометь «Заменено №M», но не удаляй.

Формат записи: номер, заголовок, решение, почему.

## 1. Стек: FastAPI + SQLAlchemy 2.0 (async, ORM) + Alembic

- **Решение:** ORM в стиле 2.0 (`Mapped`, `mapped_column`, `select()`), `AsyncSession`, миграции через Alembic.
- **Почему:** требование вакансии; стиль 1.x (`Column`, `session.query`) устарел.

## 2. Тонкий бэкенд-прокси между фронтом и Keitaro

- **Решение:** фронт ходит только в наше API, бэкенд ходит в Keitaro.
- **Почему:** API-ключ не должен попадать в браузер; CORS; сценарии из нескольких запросов держим на сервере.

## 3. Свой клиент Keitaro на `httpx.AsyncClient`

- **Решение:** не используем сторонние SDK.
- **Почему:** официального Python SDK нет; keitaropy синхронный, aiokeitaro заброшен.

## 4. Слои: `api → services → repositories / clients → db`

- **Решение:** `api/` (роутеры), `services/` (логика), `schemas/` (Pydantic), `models/` (SQLAlchemy),
  `repositories/`, `db/`, `clients/keitaro/`, `core/config.py`.
- **Почему:** аналог Go-структуры handlers/services/domain/repos/db; сервисы не зависят от FastAPI и тестируются отдельно.

## 5. Pydantic-схемы отдельно от ORM-моделей

- **Решение:** `schemas/` и `models/` не смешиваются.
- **Почему:** ORM-объекты завязаны на сессию и ленивые загрузки; DTO и таблицы меняются по разным причинам.

## 6. Модели Keitaro отдельно от наших

- **Решение:** ответы Keitaro описаны в `clients/keitaro/schemas.py`.
- **Почему:** изменения их API не расползаются по нашему коду.

## 7. Что хранится в БД

- **Решение:** реестр созданных кампаний, журнал изменений офферов, кэш справочников.
- **Почему:** Keitaro остаётся источником правды; храним только то, чего в нём нет.

## 8. Откат при сбое создания кампании

- **Решение:** если после создания кампании упал запрос на поток, удаляем созданную кампанию.
- **Почему:** не оставлять полуготовые кампании в Keitaro.

## 9. Geo — список стран через запятую

- **Решение:** поле принимает одну или несколько стран.
- **Почему:** в макете список, в тексте ТЗ одна страна; список покрывает оба случая.

## 10. Фронт: Jinja2 + Alpine.js, отдаётся из FastAPI

- **Решение:** без React и сборки на Node.
- **Почему:** две формы; весь проект на Python, запуск одной командой.

## 11. SQLite (`aiosqlite`) по умолчанию

- **Решение:** Postgres подключается сменой `DB_URL`.
- **Почему:** простой запуск для проверяющих.

## 12. TDD

- **Решение:** код пишется только через Red → Green → Refactor (правила в AGENTS.md).
- **Почему:** требование к процессу; тесты на моках Keitaro позволяют работать без доступа к инстансу.

## 13. Состояние проекта: git + PLAN.md + DECISIONS.md

*Заменено №14.*

- **Решение:** история — в git, план и открытые вопросы — в `docs/PLAN.md`, решения — здесь.
  Указания для агентов — в `AGENTS.md`, `CLAUDE.md` ссылается на него.
- **Почему:** не дублировать историю git; `AGENTS.md` читают Cursor и Windsurf, `CLAUDE.md` — Claude Code.

## 14. План с галочками; git ведёт только пользователь

*Заменяет №13.*

- **Решение:** `docs/PLAN.md` хранит все шаги с чекбоксами: сделанные `[x]` остаются, текущий помечен.
  Агент читает git (`log`, `status`, `diff`), но не делает коммиты и не пушит.
  Указания для агентов — в `AGENTS.md`, `CLAUDE.md` ссылается на него.
- **Почему:** коммиты делает пользователь, поэтому прогресс должен быть виден в плане, а не только в git;
  `AGENTS.md` читают Cursor и Windsurf, `CLAUDE.md` — Claude Code.
